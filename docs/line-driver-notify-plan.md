# แผนออกแบบ: เชื่อมระบบจองรถเข้ากับ LINE กลุ่มคนขับ + หน้าเว็บปฏิทินงานคนขับ

> **สถานะ (อัปเดตล่าสุด)**: เฟส 1 (แจ้งเตือนอัตโนมัติ) และเฟส 2 (หน้าเว็บปฏิทินงานคนขับ) เขียนโค้ด
> เสร็จแล้ว ผ่าน `tsc --noEmit`/`eslint --max-warnings=0` ทั้งคู่ — **เหลือแค่เฟส 0 (ตั้งค่า LINE
> Official Account ที่ต้องทำนอกโค้ด — ดูข้อ 2)** ที่ต้องทำก่อนถึงจะเห็นข้อความเด้งเข้ากลุ่มจริง โค้ด
> ที่ deploy ไปแล้วตอนนี้จะ "เงียบ" (ไม่ส่งอะไรเลย ไม่ error) จนกว่าจะตั้งค่า env var สองตัวครบ —
> ดูข้อ 7 (Checklist ก่อนใช้งานจริง) ท้ายเอกสาร

เอกสารนี้สรุปแนวทางเชื่อมระบบทะเบียนครุภัณฑ์/จองรถ-ห้องประชุม (Next.js + Google Sheets) เข้ากับ
LINE กลุ่มแชทของพนักงานขับรถ ตามที่ตกลงกัน 3 ข้อ:

1. **แพลตฟอร์ม**: LINE Messaging API ผ่าน LINE Official Account (LINE Notify ถูกปิดให้บริการไปแล้วตั้งแต่
   31 มี.ค. 2568 — LINE แนะนำให้ย้ายมาใช้ Messaging API แทน จึงเป็นทางเลือกเดียวที่ยังใช้งานได้จริงในปัจจุบัน)
2. **ปฏิทินงานคนขับ**: หน้าเว็บสาธารณะ ไม่ต้องล็อกอิน เข้าผ่านลิงก์ที่ส่งมาในข้อความแจ้งเตือน
3. **ขอบเขตการแจ้งเตือน**: ครอบคลุมทุกเหตุการณ์ที่กระทบงานของคนขับ (จ่ายรถ/อนุมัติใหม่, แก้ไขใบสั่งงาน,
   แยกรายการออก, ยกเลิกคำขอที่อยู่ในเที่ยวที่จ่ายไปแล้ว)

## 1. ภาพรวมสถาปัตยกรรม

```
[ฝ่ายบริหารกดอนุมัติ/แก้ไข/แยก/ยกเลิก ในเว็บ]
              │
              ▼
   API route เดิม (Next.js, บน Vercel)
   POST/PATCH/DELETE /api/booking/...
              │  (หลังบันทึกลง Google Sheets สำเร็จ)
              ▼
   lib/lineNotify.ts  →  LINE Messaging API (push)
              │
              ▼
   ข้อความเด้งเข้ากลุ่ม LINE คนขับทันที
   (มีลิงก์แนบไปหน้าเว็บปฏิทินงานคนขับ)
              │
              ▼
   คนขับกดลิงก์ → หน้าเว็บสาธารณะ /driver
   (ดึงข้อมูลจาก Google Sheets ชุดเดียวกับระบบหลัก แบบ read-only ไม่ต้องล็อกอิน)
```

ไม่ต้องมีเซิร์ฟเวอร์ใหม่ ไม่ต้องมี background job — ทุกอย่างยิงแบบ "fire-and-forget" ตรงจาก API
route ที่มีอยู่แล้ว ณ จังหวะที่บันทึกข้อมูลสำเร็จ เพราะปริมาณงาน (จองรถ/วัน) ของโรงพยาบาลขนาดนี้
ไม่จำเป็นต้องมีคิวข้อความแยกต่างหาก

## 2. ส่วนที่ 1 — ตั้งค่า LINE Official Account (งานที่ไม่ใช่โค้ด ทำครั้งเดียว)

ขั้นตอนนี้ทำโดยฝ่ายที่ดูแล LINE ของโรงพยาบาล (ไม่จำเป็นต้องเป็นโปรแกรมเมอร์):

1. สร้าง **LINE Official Account** (ถ้ายังไม่มี) ผ่าน [LINE Official Account Manager](https://www.linebiz.com/th/)
   — ใช้ชื่อที่คนขับจำได้ เช่น "รถโรงพยาบาลท่าตะเกียบ"
2. เปิดใช้งาน **Messaging API** ให้ OA นี้ผ่าน [LINE Developers Console](https://developers.line.biz/console/)
   จะได้:
   - **Channel access token** (ใช้ยิงข้อความออกจากเซิร์ฟเวอร์)
   - **Channel secret** (ใช้ยืนยัน webhook ถ้ามีในอนาคต — เฟสนี้ยังไม่จำเป็นต้องใช้)
3. ในตั้งค่าช่องทาง เปิด **"Allow bot to join group chats"** (ปิดอยู่โดยค่าเริ่มต้น)
4. เชิญ OA นี้เข้า **กลุ่ม LINE ที่คนขับใช้อยู่แล้ว** เหมือนเชิญเพื่อนเข้ากลุ่มปกติ
5. ดึง **Group ID** ของกลุ่มนั้นออกมา (ใช้ครั้งเดียว แล้วเก็บไว้ถาวร) — วิธีง่ายที่สุดคือเปิด
   webhook ชั่วคราว (endpoint พื้นฐาน 1 ไฟล์) ให้พิมพ์ log เมื่อมีข้อความเข้ากลุ่ม แล้วอ่านค่า
   `source.groupId` จาก payload ที่ส่งมา จากนั้นปิด/ลบ endpoint นั้นทิ้งได้เลย
6. นำ **Channel access token** และ **Group ID** ไปตั้งเป็น **Environment Variables** บน Vercel
   (เช่น `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_DRIVER_GROUP_ID`) — ห้าม commit ค่าเหล่านี้ลง repo
   เด็ดขาด ตามแนวทางความปลอดภัยเดียวกับ `GOOGLE_SHEET_ID`/บัญชีบริการ Google ที่ใช้อยู่แล้ว

> **เรื่องค่าใช้จ่ายที่ต้องรู้**: แพ็กเกจฟรีของ Messaging API ให้ส่งข้อความแบบ push ได้ **200
> ข้อความ/เดือน** เท่านั้น (ตอบกลับ webhook ขาเข้าไม่นับโควตา) ถ้าปริมาณจ่ายรถ/แก้ไข/ยกเลิกต่อเดือน
> เกิน 200 ครั้ง ต้องอัปเกรดแพ็กเกจ (มีราคาแบบ THB แยกในคอนโซลของบัญชีไทย ควรเช็กราคาจริงตอนสมัคร)
> แนะนำให้ประเมินคร่าวๆ ก่อนเริ่ม: เที่ยวรถเฉลี่ยต่อวัน × 30 วัน × จำนวนเหตุการณ์ต่อเที่ยว
> (จ่ายรถ 1 + แก้ไข/ยกเลิกเป็นบางครั้ง) ว่าจะพอ 200 หรือไม่

## 3. ส่วนที่ 2 — ระบบแจ้งเตือนอัตโนมัติ (โค้ดที่ต้องเพิ่ม)

### 3.1 ไฟล์ใหม่: `lib/lineNotify.ts`

ฟังก์ชันเดียว ยิง POST ไปที่ `https://api.line.me/v2/bot/message/push` พร้อม
`Authorization: Bearer <token>` และ body `{ to: <groupId>, messages: [{ type: "text", text }] }`

หลักการสำคัญ: **best-effort เสมอ** — ครอบด้วย try/catch แล้ว log error ไว้เฉยๆ ห้ามปล่อยให้
ข้อผิดพลาดจาก LINE (เช่น token หมดอายุ, กลุ่มโควตาเต็ม) ทำให้การอนุมัติ/แก้ไข/ยกเลิกจองรถในระบบ
ล้มเหลวตามไปด้วย — เหมือนแนวทาง "best-effort" ที่ใช้กับ `getUsers()`/`appendEditLog` บางจุดใน
โค้ดฐานนี้อยู่แล้ว

### 3.2 จุดที่ต้องเรียกใช้ (hook เข้ากับ route ที่มีอยู่แล้ว)

| เหตุการณ์ | ไฟล์/ฟังก์ชันที่เกี่ยวข้อง | เนื้อหาข้อความ (ตัวอย่าง) |
|---|---|---|
| จ่ายรถ/อนุมัติใหม่ | `POST /api/booking/trip-orders` (หลัง `createTripOrder` สำเร็จ) | 🚐 มีงานใหม่ • รถตู้ (นข 6005) • คนขับ: สมชาย • ออกเดินทาง 07:30 • ผู้โดยสารรวม 9 คน • [ดูรายละเอียด] |
| แก้ไขใบสั่งงาน | `PATCH /api/booking/trip-orders/[tripOrderId]` (หลัง `updateTripOrder` สำเร็จ เมื่อรถ/คนขับ/เวลาเปลี่ยน) | ✏️ แก้ไขงาน • รถตู้ (นข 6005) • เปลี่ยนเวลาออกเป็น 08:00 • [ดูรายละเอียด] |
| แยกรายการออก | `PATCH .../[tripOrderId]` (หลัง `splitBookingFromTripOrder` สำเร็จ — ฟีเจอร์ที่เพิ่งทำไว้) | ⚠️ มีรายการถูกแยกออกจากเที่ยว • รถตู้ (นข 6005) • ผู้โดยสารเหลือ 6 คน (เดิม 9) • [ดูรายละเอียด] |
| ยกเลิกคำขอที่อยู่ในเที่ยวที่จ่ายแล้ว | `DELETE /api/booking/bookings/[bookingId]` (หลัง `cancelBooking` สำเร็จ **และ** คำขอนั้นมี `tripOrderId` อยู่) | ❌ มีการยกเลิกคำขอในเที่ยว • รถตู้ (นข 6005) • ผู้โดยสารเหลือ 5 คน • [ดูรายละเอียด] |

ทุกข้อความแนบลิงก์ไปหน้าเว็บปฏิทินงานคนขับ (ส่วนที่ 4) ท้ายข้อความเสมอ ให้กดดูรายละเอียดเต็ม
ต่อได้ทันทีโดยไม่ต้องพิมพ์ค้นหาเอง

> **หมายเหตุขอบเขต**: คำขอจองรถใหม่ที่ "รออนุมัติ" (ยังไม่ถูกจ่ายรถ) จะ**ไม่**แจ้งเข้ากลุ่มคนขับ
> เพราะยังไม่ใช่งานของคนขับจนกว่าฝ่ายบริหารจะจ่ายรถจริง (กระดิ่งแจ้งเตือนในเว็บที่มีอยู่แล้วดูแล
> เคสนี้สำหรับฝ่ายอนุมัติอยู่แล้ว) — ถ้าต้องการให้แจ้งคำขอ "รออนุมัติ" เข้ากลุ่มคนขับด้วยก็ทำเพิ่มได้
> ภายหลัง แต่เบื้องต้นเสนอให้เริ่มเฉพาะเหตุการณ์ที่กระทบงานที่ตัดสินใจแล้วก่อน กันข้อความรบกวน
> เกินจำเป็นและกันโควตา 200 ข้อความ/เดือนหมดเร็ว

## 4. ส่วนที่ 3 — หน้าเว็บ "ปฏิทินงานคนขับ" (สาธารณะ ไม่ต้องล็อกอิน)

### 4.1 เส้นทาง URL

เสนอ route ใหม่ เช่น `/driver` — ไม่ผูกกับระบบ session/login เดิมเลย (คนขับไม่มีบัญชีในระบบอยู่แล้ว
ตามที่ตรวจสอบจากโค้ดปัจจุบัน — ชื่อคนขับเป็นแค่ข้อความอิสระในใบสั่งงาน ไม่ใช่บัญชีผู้ใช้)

เพื่อไม่ให้ URL นี้ถูกเดาได้ง่ายเกินไป (แม้ข้อมูลจะไม่ลับมากเพราะพนักงานทั้งโรงพยาบาลเห็นปฏิทินนี้
อยู่แล้วในระบบหลัก) แนะนำ:
- ใส่ `<meta name="robots" content="noindex">` กันหลุดไปอยู่บน Google
- (ทางเลือกเสริม ไม่บังคับ) ใช้ path ที่เดายากกว่า `/driver` ตรงๆ เช่น `/driver/xxxxxxxx` ด้วย slug
  คงที่ค่าหนึ่งที่ตั้งไว้ใน env var แล้วแจกให้คนขับครั้งเดียว (กันคนนอกกลุ่มเปิดเจอโดยบังเอิญ)

### 4.2 ข้อมูลที่จะแสดง / ไม่แสดง

หน้านี้ **อ่านอย่างเดียว** ดึงจาก Google Sheets ชุดเดียวกับระบบหลัก (ผ่าน API endpoint ใหม่ที่ไม่
เช็ก session) แต่ควรคัดเฉพาะฟิลด์ที่จำเป็นต่องานขับรถจริงๆ ไม่ทั้งหมดเหมือนหน้า BookingCalendar
ของฝ่ายบริหาร:

**แสดง**: วันที่/เวลาออกเดินทาง–สิ้นสุด, รถ+ป้ายทะเบียน, ชื่อคนขับ, ปลายทาง, จำนวนผู้โดยสารรวม,
กลุ่มงาน/ผู้จองแต่ละคำขอในเที่ยวเดียวกัน, สถานะ (จ่ายแล้ว/ยกเลิกบางส่วน)

**ไม่แสดง (แนะนำ)**: เบอร์โทรติดต่อของผู้จอง (ข้อมูลส่วนบุคคล ไม่จำเป็นต่อคนขับ ถ้าต้องติดต่อ
ผู้จองให้ประสานผ่านฝ่ายบริหารแทน) — จุดนี้ปรับได้ตามต้องการ ถ้าคนขับต้องโทรประสานตรงกับผู้จองเอง
ก็ใส่กลับมาได้ ให้แจ้งตอนเริ่มพัฒนาจริง

### 4.3 การจัดวางหน้าจอ (mobile-first)

ต่างจากปฏิทินฝ่ายบริหาร (ปฏิทินเต็มเดือน) — หน้าคนขับควรเป็น **รายการ (list) เรียงตามเวลา** เริ่ม
จาก "วันนี้" ไล่ไปข้างหน้า 7 วัน เพราะคนขับใช้บนมือถือ อ่านลิสต์เร็วกว่ากดดูปฏิทินกริด:

```
วันนี้ (25 ก.ย. 2569)
┌──────────────────────────────┐
│ 07:30–18:00  รถตู้ (นข 6005)  │
│ คนขับ: สมชาย                  │
│ รวม 3 คำขอ • ผู้โดยสาร 9 คน    │
│ ปลายทาง: รพ.สรรพสิทธิประสงค์   │
└──────────────────────────────┘

พรุ่งนี้ (26 ก.ย. 2569)
┌──────────────────────────────┐
│ ...                            │
└──────────────────────────────┘
```

แต่ละการ์ดกดขยายดูรายละเอียดคำขอย่อยได้ (คล้าย DayDetailModal เดิม แต่แบบง่ายกว่า ไม่มีปุ่มจัดการ
ใดๆ เพราะเป็นแค่หน้าดูอย่างเดียว)

### 4.4 API endpoint (เขียนเสร็จแล้ว)

`GET /api/public/driver-trips` — ไม่เช็ก session cookie เหมือน route อื่น เรียก `getDriverTrips()`
ใน `lib/sheets.ts` (ฟังก์ชันเดียว ใช้ร่วมกับ `/driver` ตอนเรนเดอร์ครั้งแรกด้วย กันสองจุดคำนวณเพี้ยน
ไปจากกัน) ซึ่ง:
- คืนเฉพาะฟิลด์ตามข้อ 4.2 (ไม่ส่งเบอร์โทรผู้จองออกไป — ตัดสินใจแล้วตามค่าที่แนะนำในข้อ 6 เดิม)
- กรองเฉพาะเที่ยวที่ "จ่ายรถแล้ว" จริง (มีใบสั่งงานคุมอยู่ และยังเหลือคำขอที่ไม่ถูกยกเลิกอย่างน้อย 1
  รายการ) — คำขอที่ยัง "รออนุมัติ" ไม่แสดง
- จำกัดช่วงวันนี้ถึง +14 วัน (ตามเขตเวลา Asia/Bangkok ตรงๆ ไม่ใช่ UTC ของเซิร์ฟเวอร์)

## 6. การตัดสินใจที่ใช้ไปแล้วในโค้ดที่เขียนเสร็จ (ปรับทีหลังได้)

1. **ข้อความภาษา/โทน** — กันเองแบบกระชับ มีอีโมจิบอกประเภทเหตุการณ์ (🚐 งานใหม่ / ✏️ แก้ไข / ⚠️
   แยกรายการ / ❌ ยกเลิก) ดูข้อความจริงในตาราง 3.2 — อยากเปลี่ยนโทน/ข้อความ แก้ที่
   `src/app/api/booking/trip-orders/route.ts`, `.../[tripOrderId]/route.ts` และ
   `src/app/api/booking/bookings/[bookingId]/route.ts` (จุดที่เรียก `notifyDriverGroup(...)`)
2. **เบอร์โทรผู้จอง** — **ไม่แสดง** ในหน้า `/driver` ตามคำแนะนำเดิม (ดูข้อ 4.2) ถ้าอยากเพิ่มกลับมา
   ทีหลัง แก้ที่ `getDriverTrips()` ใน `lib/sheets.ts` (เพิ่มฟิลด์ `contactPhone` เข้า
   `DriverTripRequestSummary`) และที่ `DriverCalendar.tsx` (เพิ่มการแสดงผล)
3. **URL ปฏิทินคนขับ** — ใช้ `/driver` ตรงๆ (ไม่ใส่ slug สุ่ม) พร้อม `robots: noindex` กันหลุดไปอยู่บน
   Google — รองรับเปลี่ยนเป็น path ที่เดายากกว่าได้ทันทีโดยไม่ต้องแก้โค้ดเพิ่ม ผ่าน env var
   `DRIVER_CALENDAR_PATH` (เช่นตั้งเป็น `/driver/a1b2c3d4`) — ดูคอมเมนต์ที่ `driverCalendarUrl()` ใน
   `lib/lineNotify.ts`
4. **แพ็กเกจ LINE** — ยังไม่ได้เช็ก (ต้องทำในเฟส 0 ที่บัญชี LINE Developers ของโรงพยาบาลเอง ดูข้อ 7)

## 7. Checklist ก่อนใช้งานจริง (เฟส 0 — ทำนอกโค้ด)

โค้ดทั้งหมด (เฟส 1-2) deploy ได้เลยตอนนี้โดยไม่กระทบระบบเดิมแม้แต่น้อย — ฟังก์ชัน
`notifyDriverGroup()`/`notifyDirector()` จะ "เงียบ" (ไม่ส่งอะไร ไม่ error) จนกว่าจะตั้งค่าครบ:

1. ทำตามขั้นตอนในข้อ 2 ของเอกสารนี้ (สร้าง LINE OA → เปิด Messaging API → เชิญเข้ากลุ่มคนขับ →
   ดึง Group ID) ให้ได้ **Channel access token** และ **Group ID** ของกลุ่มคนขับ
2. (สำหรับแจ้งเตือน ผอ. — ตามที่ขอเพิ่ม "อยากให้มีการแจ้งเตือนทาง line ให้กับผอ.ได้รับทราบว่ามี
   การขอรถเข้ามาด้วยครับ") เพิ่มเพื่อน OA ตัวเดียวกันด้วยบัญชี LINE ของ ผอ. เอง (แชท 1-1 ธรรมดา
   ไม่ต้องสร้างกลุ่มใหม่) แล้วดึง **User ID** ของ ผอ. ออกมาด้วยวิธีเดียวกับที่ข้อ 2.5 ของเอกสารนี้
   แนะนำสำหรับ Group ID (เปิด webhook ชั่วคราว อ่าน `source.userId` จาก payload แทน `source.groupId`)
   — หรือจะตั้งเป็น Group ID ของกลุ่มที่ ผอ. อยู่ด้วยก็ได้เหมือนกัน (LINE push API รับได้ทั้งสองแบบ)
3. ตั้งค่า Environment Variables บน Vercel (Project Settings → Environment Variables):
   - `LINE_CHANNEL_ACCESS_TOKEN` = token ที่ได้จากข้อ 1 (ใช้ร่วมกันทั้งสองปลายทาง)
   - `LINE_DRIVER_GROUP_ID` = Group ID ที่ได้จากข้อ 1
   - `LINE_DIRECTOR_USER_ID` = User ID (หรือ Group ID) ของ ผอ. ที่ได้จากข้อ 2 — ไม่ตั้งค่าตัวนี้
     ก็ไม่กระทบการแจ้งเตือนกลุ่มคนขับเลย แค่จะไม่มีข้อความไปหา ผอ. เท่านั้น (ข้ามเงียบๆ เหมือนกัน)
   (ตัวเลือกเสริม ไม่บังคับ: `DRIVER_CALENDAR_PATH` ถ้าอยากเปลี่ยน URL ปฏิทินคนขับจาก `/driver`
   เป็น path ที่เดายากกว่า — ดูข้อ 6.3)
4. Redeploy โปรเจกต์ (ตั้งค่า env var ใหม่ต้อง deploy ใหม่ถึงจะมีผล — ปกติของ Vercel)
5. ทดสอบ: กดจ่ายรถ 1 เที่ยวในระบบจริง (หรือกลุ่ม/แชททดลองก่อนก็ได้ตามเฟส 3) แล้วดูว่าข้อความเด้ง
   เข้ากลุ่มคนขับและแชทของ ผอ. ไหม พร้อมลองกดลิงก์ในข้อความว่าไปหน้า `/driver`/`/director` ได้จริง
6. เช็กโควตา LINE (200 ข้อความ/เดือนฟรี) เทียบกับปริมาณจ่ายรถจริงของโรงพยาบาล ตามข้อ 6.4 — ตอนนี้
   แต่ละครั้งที่จ่ายรถจะยิง 2 ข้อความ (กลุ่มคนขับ + ผอ.) ไม่ใช่ 1 ข้อความเหมือนก่อนหน้านี้แล้ว
